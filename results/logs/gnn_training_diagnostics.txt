What I took from this
- Patience 10 was too short: the GraphSAGE validation curve dips after the first epochs and
  recovers later (default config: 0.0992 at epoch 2, 0.1056 at epoch 33). Patience was raised to
  20 for every trained model so the comparison stays fair.
- Larger learning rates / smaller batches make the training loss go much lower (0.12-0.15) while
  validation recall collapses to ~0.07 after its peak -> the GNNs with learned transforms overfit.
  More L2 or dropout did not change the peak (~0.106).
- GAT shows the same pattern, even stronger (peak 0.107, then 0.072).
- One SAGE layer (0.114) is better than two (0.106).
- LightGCN-style propagation (no weight matrices, no nonlinearity) with exactly the same training
  setup reaches 0.119 and is still improving at epoch 60, i.e. better than MF.
  So the graph propagation itself helps on this data, the learned per-layer transforms are what
  hurts. LightGCN was added to the experiments as a reference model because of this, and the
  GraphSAGE/GAT tuning grid now includes l2 / dropout / learning-rate stages.

Second problem: the unknown-user embedding in GAT / GraphSAGE (same day, later)
================================================================================
With patience 20 the GAT tuning runs still stopped early (val recall@20 ~0.096-0.099). The training
loss stayed on a plateau (~0.278) for ~12 epochs, then dropped quickly, and exactly then the
validation recall fell from ~0.096 to ~0.065 and never recovered.

First guess was that the unregularised layer weights inflate the output norms. Regularising the
output embeddings instead of the layer-0 embeddings changed nothing (GAT, seed 42, 45 epochs):

Logging the validation recall per user group showed what actually happens (GAT, seed 42):
    overall  [0.0844, 0.0935, 0.0955, 0.0965, 0.0963, 0.0961, 0.0661, 0.0665, 0.0651, 0.067]  (every 2nd epoch)
    warm     [0.076, 0.083, 0.085, 0.086, 0.086, 0.086, 0.103, 0.104, 0.103, 0.104]
    cold     [0.098, 0.111, 0.111, 0.112, 0.113, 0.111, 0.004, 0.002, 0.001, 0.004]
When the model leaves the plateau, warm users get *better* (0.086 -> 0.103) and cold users drop to
~0. 36% of the validation users are cold, so the overall metric falls and early stopping keeps
the epoch before the transition, i.e. a model that is popularity-like for everybody.

Cause: cold users are represented by the unknown-user embedding. Id dropout trained that row by
hiding the id of 10% of the users in each step, but those users kept their edges. At inference a
cold user has the unknown id and *no* edges, a combination the model never saw in training. MF
and LightGCN are not affected (no edges / no weights: the result is a scaled copy of the trained
unknown row), weighted GNN layers turn it into something arbitrary.

Fix (models/gnn.py, cold_simulation=True): users (and items, for the content models) whose id is
dropped in a step also lose all their edges in that step. Same runs after the fix (40 epochs):

Correction to the first section: the "validation recall collapses to ~0.07 while the training
loss keeps falling" runs (larger lr / smaller batches) were most likely the same cold-user effect,
not ordinary overfitting. Those runs only logged the overall metric, so this cannot be checked
afterwards. Lesson: log the validation metric per user group from the start.
